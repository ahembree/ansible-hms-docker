To easily update from this git repo _**and**_ update your custom variable names (due to deprecating/renaming variables) if you are on a previous release, run:

```bash
make update
```

Previous variable names will still work for at least a year after the change. While any are still in use, the playbook lists them in a warning at the start of each run. Please update to resolve.

`make update` renames the variables in your `inventory/group_vars/all/*.yml` files, including where one variable is used in the value of another (`{{ ... }}`). Before it changes anything, it saves a copy of those files to `inventory/backups/<date and time>/`. The full list of renames is in [`migrations/variable_renames.yml`](https://github.com/ahembree/ansible-hms-docker/blob/master/migrations/variable_renames.yml). To only rename the variables and merge new container map entries, without pulling, run `make migrate-config`.

:::note[Variable names]

Every setting was renamed to start with `hmsdocker_`, for example `hms_docker_domain` is now `hmsdocker_domain` and `traefik_ssl_enabled` is now `hmsdocker_traefik_ssl_enabled`.

If you are updating from v1.20 or older, the first `make update` still runs the old update steps and does not rename them. Run `make update` a second time (or `make migrate-config`) to rename them. Until then the old names keep working.

:::

If any new containers or container controls were added since you last updated, your `container_map.yml` file will also be updated with the defaults for the new container(s) and controls. The defaults come from the version of the code you just pulled, so they always match what you are about to apply.

## Release channels

The repo has two long-lived branches:

| Branch | Channel | What it contains |
|-|-|-|
| `master` | Stable (default) | Only released versions. It only changes when a new [release](/docs/release-notes/) is published. |
| `develop` | Development | Every merged change, including ones that are not in a release yet. Can be unstable. |

`make update` pulls whichever branch you currently have checked out, so a normal clone stays on stable releases.

To try changes before they are released, switch to `develop`:

```bash
make switch-develop
```

To go back to stable releases:

```bash
make switch-stable
```

Both commands switch branches and run `make update` for you. Local edits such as `inventory/hosts.yml` are kept; if an edited file also changed between the branches, git refuses and you need to commit or stash it first. To see which branch you are on, run `make branch`.

:::caution[Switching back to stable]

Moving from `develop` to `master` can roll back changes that were already applied to your host. If `develop` added a container that is not in the latest release yet, `make update` warns about it. Disable it in your `container_map.yml` before running `make apply`.

If `make update` renamed your variables while you were on `develop` and the latest release does not know the new names yet, copy your previous files back from `inventory/backups/` after switching.

:::

Please see the [Release Notes](/docs/release-notes/) if you are updating from a previous version.

:::note[Note]

If you are running before version 1.9.0, you may need to append an additional patch version to your version file.

If your `/opt/hms-docker/.hmsd-version` only has a major and minor version (eg. `1.8`), add a patch version by adding another `.0` to the end (eg. `1.8.0`)

:::
