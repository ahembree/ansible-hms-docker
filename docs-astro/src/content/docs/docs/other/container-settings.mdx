## Global Container Settings

These settings apply to all containers and are configured in `inventory/group_vars/all/container_settings.yml`

### Container State

```yaml
hms_docker_compose_container_state: present
```

Controls whether containers should exist. Valid values: `present`, `absent`. Setting to `absent` will remove all containers.

### Restart Policy

```yaml
container_restart_policy: unless-stopped
```

Controls how containers behave when the Docker daemon or server restarts. Valid values:

- `unless-stopped` (default) — Restarts automatically unless manually stopped
- `always` — Always restarts regardless of exit status
- `on-failure` — Only restarts if the container exits with a non-zero exit code

### Auto-Update Schedule

```yaml
container_auto_update_schedule: "0 0 9 * * *"
```

The cron schedule (in UTC) for Watchtower to check for container image updates. The default checks daily at 9:00 AM UTC.

### Remove Orphans

```yaml
container_remove_orphans: yes
```

When enabled, containers that are disabled in the container map will be automatically stopped and removed on the next playbook run.

### Timezone

```yaml
container_timezone: America/New_York
```

The timezone passed to containers via the `TZ` environment variable. Use a valid [TZ database name](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones).

### User and Group IDs

```yaml
container_uid: 1234
container_gid: 1234
```

The UID and GID used for running processes inside containers. These should match the user that owns your media files to avoid permission issues.

:::caution[Warning]

Changing these values after initial setup may cause permission issues with existing container data and media files.

:::

### Global Port Exposure

```yaml
container_expose_ports: no
```

When set to `yes`, all container ports will be exposed on the host. If Traefik is disabled in the container map, this is automatically overridden to `yes`.

For per-container port exposure, use the `expose_ports` setting in the [Container Map](/docs/container-list/#container-map).

### Read-Only Media Mounts

```yaml
hmsdocker_readonly_media_containers: []
```

A list of containers that get the media share (`hms_docker_mount_path`) mounted read-only, for example:

```yaml
hmsdocker_readonly_media_containers: ["plex", "jellyfin"]
```

Each listed container still sees the media share at `/data`, but the mount is made with `:ro`. The container can read and play everything, but it cannot create, change, or delete anything on the share. This limits the damage a compromised or misbehaving media server can do. It cannot delete your library or encrypt it for ransom.

Supported containers: `plex`, `emby`, `jellyfin`, `kavita`, `calibre`.

Any other container is not supported, including the ones that need to write to the media share (the Sonarr/Radarr family, the download clients, `tdarr`, and so on). If you list an unsupported container, or misspell a name, the playbook shows a preflight warning and that container's mount stays writable.

:::caution[Features that stop working]

Anything that writes into the media folders fails once the share is read-only. Change these settings in the app so it stores the data in its own config folder instead, or accept that the feature is unavailable.

**Plex**
- Deleting media from within Plex ("Allow media deletion")
- Optimized versions, if they are saved next to the media (the default)
- DVR recordings saved into the library

**Jellyfin and Emby**
- Saving NFO metadata files ("Nfo" metadata saver)
- "Save artwork into media folders"
- Saving downloaded subtitles into media folders
- Saving trickplay / thumbnail images next to the media
- Saving downloaded lyrics into media folders (Jellyfin)
- Deleting media from within the app
- DVR / Live TV recordings saved into the library

**Calibre**
- Adding, editing, converting, or deleting books in a Calibre library that lives on the media share. A library kept in Calibre's own `/config` folder is not affected.

**Kavita**
- Kavita does not normally write to the library, so nothing should change.

Playback, library scans, and anything the app stores in its own config folder (watch history, posters it does not save into media folders, and so on) keep working.

:::

:::caution[Additional NAS shares on older kernels]

If you mount [additional NAS shares](/docs/getting-started/nas/#additional-nas-mounts) inside `hms_docker_mount_path` (the recommended setup), they only become read-only on Linux kernel 5.12 or later (with Docker 25 or later, which the playbook installs). On older kernels (for example Alma/Rocky/RHEL 8 or Debian 11), Docker cannot make the shares mounted under `/data` read-only, so containers listed here can still write to them. The playbook shows a preflight warning when this applies.

:::

:::note

The Sonarr/Radarr family and the download clients still write to the media share as before. A read-only media server can always read new files as soon as they are imported.

:::

## Advanced Settings

These settings are configured in `inventory/group_vars/all/hmsd_advanced.yml`

### Project Name

```yaml
project_name: hms-docker
```

Controls the base folder name used for the project. This affects:

- Data path: `/opt/<project_name>/`
- Docker Compose project name
- Docker network names (e.g., `<project_name>_proxy_net`)

### Data Path

```yaml
hms_docker_data_path: "/opt/{{ project_name }}"
```

Where all container data, configs, compose files, and secrets are stored. See the [File/Folder Layout](/docs/other/paths/) docs for the full directory structure.

### Apps Path

```yaml
hms_docker_apps_path: "{{ hms_docker_data_path }}/apps"
```

The directory where each container's per-app data and configuration is stored (one subdirectory per container, e.g. `apps/sonarr/config`). Defaults to a subdirectory of `hms_docker_data_path` and rarely needs to be changed.

### Docker Network Subnet

```yaml
hmsdocker_docker_network_base_subnet: "172.27.0.0/16"
```

The IP range used for all Docker networks. Individual `/24` subnets are provisioned from this block for each Docker network. Change this if it overlaps with your internal network range.

### Host Network Settings

```yaml
hms_docker_subnet_mask: "24"
```

Your local network subnet mask (e.g., for a `192.168.1.0/24` network, use `24`). Used to generate Traefik IP allowlist rules and configure how some containers (Plex, Transmission) treat local network traffic.

### Secrets File Permissions

```yaml
secrets_env_user: root
secrets_env_group: root
secrets_env_mode: "0600"
```

Controls the ownership and permissions of the `.env` file containing API keys and secrets. See the [Secrets files](/docs/other/paths/#secrets-files) section in the File/Folder Layout docs for more details on adjusting these.
