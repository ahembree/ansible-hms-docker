## v1.21.0

Adds an optional [Docker socket proxy](https://hmsdocker.dev/docs/services/socket-proxy/). Containers that use the Docker socket currently get full access to it, which is the same as root access on the host. Mounting the socket read-only (`:ro`) does not limit that. With the socket proxy enabled, each of these containers gets its own [socket-proxy](https://github.com/wollomatic/socket-proxy) container that only allows the Docker API requests that container needs.

It is disabled by default. Nothing changes until you enable it.

### New Containers

- `socket-proxy`: one `socket-proxy-<container>` container per supported container, each with its own filtered socket and no network access

### What changes when it is enabled

- Traefik, Homepage and Uptime Kuma can only read containers (and events for Traefik, stats for Homepage)
- The Beszel agent can only read containers, their stats and logs
- Watchtower and the Authentik worker can only make the requests they need to pull images and recreate containers. Containers created by Authentik cannot bind mount host folders
- FileFlows no longer gets the Docker socket. It only used it for the optional "Docker Siblings" runners, which this project does not set up
- Netdata, Portainer and Dockhand keep the Docker socket. Netdata mounts the whole host filesystem, and Portainer and Dockhand need the whole Docker API
- Running commands in containers (`exec`), volumes, image builds and pruning are blocked for all proxied containers

### Required Steps

None, unless you enable the socket proxy. To enable it, set `enabled: true` for `socket-proxy` in `inventory/group_vars/all/container_map.yml` (or run `make update` first to add the entry) and run the playbook.

**Uptime Kuma:** its Docker hosts are stored in its own database. After enabling the socket proxy, change the socket path of each Docker host under **Settings > Docker Hosts** from `/var/run/docker.sock` to `/var/run/socket-proxy/docker.sock`. Everything else is changed by the playbook.

### New Settings

In `inventory/group_vars/all/container_settings.yml`:

- `hmsdocker_socket_proxy_log_level` (default `info`): log level of the proxies. Blocked requests are logged at `warn`
- `hmsdocker_socket_proxy_overrides` (default `{}`): change the access of individual containers, or switch one back to the unfiltered socket with `mode: direct`
